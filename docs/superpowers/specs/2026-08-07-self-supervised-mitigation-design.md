# 자기지도 완화 학습 설계

**작성일**: 2026-08-07
**상태**: 승인 대기
**선행 조건**: `tier0-fallback` 브랜치 병합 (`fallback.strength.required_strength`를 사용함)

## 1. 왜 바꾸는가

지금까지의 모든 실패가 하나의 병에서 나왔다. **학습 목표와 채점 기준이 다른 것을 재고 있었다.**

| 측정 | 결과 |
|---|---|
| 합성 데이터 val_psnr | 35.66 dB |
| 실제 영상 진폭 감소 | −48.5% |
| 실제 영상 리듬 감소 | −12% |
| 모델이 달성한 PriorCalc 목표 비율 | 중앙값 **14.6%** (853프레임 중 5개만 80% 이상) |
| 실제 영상 재검증 | 위험 구간 잔존 |

손실은 `L1(출력, clean) + SSIM`이었다. 여기에는 "깜빡임"이라는 개념이 없다. 프레임을 하나씩 독립적으로 채점하므로, **모든 프레임을 같은 비율로 보정하면 손실은 만족시키면서 깜빡임 패턴은 그대로 남는다.** 실측이 정확히 그 모양이었다 — 진폭은 60% 줄었는데 밝기 방향 전환 횟수는 12%만 줄었다.

PriorCalc의 목표 히스토그램도 같은 문제를 겪었다. 마스크 **바깥** 픽셀에서 정상 밝기를 추정하는데, 합성 데이터에서는 타당하지만(평범한 영상 위에 도형을 얹었으므로) 실제 콘서트 영상에서는 마스크 안이 무대 조명이고 바깥이 관객석이다. **서로 다른 물체다.** 그래서 "조명을 관객석 밝기(0.0738)로 만들어라"는 따를 수 없는 목표가 나왔고, 모델이 15%만 따른 것은 오작동이 아니라 그림을 지키는 방어였을 가능성이 높다.

근본 원인은 **문제를 복원(restoration)으로 다루었다는 것**이다. BlazeBVD·Lai·Bonneel·Deep Video Prior 계열은 모두 "원본은 안정적이고 프레임별 처리 때문에 깜빡이게 된 영상"을 되돌린다. 우리 문제는 다르다. **콘서트 조명은 실제로 번쩍였다.** 되찾을 잠재 영상이 존재하지 않는다. README의 파이프라인이 원래 `Verifier → Fallback → 강도 상향 → 최후수단: 감광/프레임 홀드`인 것도 같은 인식이다 — 이것은 **제약 만족 문제**다.

이 설계는 학습을 그 인식에 맞춘다.

## 2. 핵심 아이디어

정답 영상을 쓰지 않는다. 손실을 세 항으로 구성한다.

```
L = L_fid + λ_t · L_temp + λ_r · L_risk
```

| 항 | 의미 | 역할 |
|---|---|---|
| `L_fid` | 출력이 **원본**에서 멀어진 정도 | "가만히 있어라" |
| `L_temp` | 연속 프레임 간 휘도 변화 | "시간축으로 평평해져라" |
| `L_risk` | **검출기 기준을 넘은 만큼** | "위험할 때만 움직여라" |

`L_fid`와 `L_risk`가 서로 민다. 그 균형점이 **딱 필요한 만큼의 보정**이다. 기준선 아래로만 내려가면 원본을 최대한 보존하는 것이 최적해가 된다.

`L_risk`가 이 설계의 핵심이다. **채점 기준을 손실 안으로 직접 가져오는 유일한 방법**이며, 1절의 병을 구조적으로 없앤다.

## 3. 손실 정의

### 3.1 충실도 `L_fid`

```
L_fid = mean |out − in|
```

`in`은 3프레임 윈도우의 중앙 프레임(= 열화된 원본)이다. 정답이 아니다.

별도의 마스크 스코핑은 필요 없다. `mitigator.arch.mitigate_frame`이 `mask * restored + (1-mask) * center`로 하드 블렌딩하므로 마스크 밖에서는 `out == in`이 항등적으로 성립하고 이 항은 0이 된다. 충실도는 자동으로 마스크 내부로 한정된다.

### 3.2 시간 일관성 `L_temp`

```
dx, dy   = estimate_global_shift(L(in_i), L(in_{i+1}))
warped   = compensate_shift(L(out_i), dx, dy)
L_temp   = mean over valid pixels of |warped − L(out_{i+1})|
```

`L(·)`은 `detector.luminance.relative_luminance`의 torch 판(`training.mitigator_losses.relative_luminance_torch`, 2026-08-06 구현됨).

**연속 출력의 차이를 0으로 몰되, `L_fid`가 저항한다.** 원본의 변화량과 비교하지 않는다 — 비교하면 깜빡임이 원본에도 있으므로 벌점이 0이 되어 항이 무력해진다.

**valid 픽셀**: `compensate_shift`가 `BORDER_REPLICATE`로 채운 가장자리는 실제 대응이 아니다. `|dx|`, `|dy|`만큼의 테두리를 제외한다.

**모션 보정은 전역 이동만 한다.** 조밀 광학 흐름을 쓰지 않는 이유는 비용이 아니라 정합성이다. `detector.pipeline._iter_scores_and_masks`가 전역 이동만 보정한 뒤 마스크를 만든다. 손실이 검출기보다 정교하게 보정하면 **검출기가 재지 않는 것을 최적화하게 되고**, 그것이 1절에서 진단한 병의 재발이다.

### 3.3 위험도 `L_risk` — 검출기 기준의 미분 가능 완화

검출기 판정은 전부 계단 함수라 기울기가 0이다. 각각을 sigmoid로 완화하되, **동일한 임계값과 동일한 결합 구조를 유지한다.**

일반 플래시 (`detector.flash.transition_mask`의 완화판):

```
delta   = |L(warped_out_i) − L(out_{i+1})|
darker  = min(L(warped_out_i), L(out_{i+1}))
soft_general = sigmoid((delta − delta_threshold) / τ)
             * sigmoid((dark_threshold − darker) / τ)
```

적색 플래시 (`detector.flash.red_flash_mask`의 완화판). 원본은 `is_saturated_red(prev) != is_saturated_red(curr)`인 **불리언 XOR**이지만, 내부 판정 `R/(R+G+B) >= threshold`는 연속량에 대한 임계이므로 완화할 수 있고, XOR은 두 소프트 지시자의 절대차로 쓸 수 있다:

```
# x ∈ {warped_out_i, out_{i+1}} — 휘도 항과 동일한 두 프레임의 RGB
ratio_x      = R_x / (R_x + G_x + B_x + eps)
soft_red_x   = sigmoid((ratio_x − red_threshold) / τ)
soft_red     = |soft_red(warped_out_i) − soft_red(out_{i+1})|
```

결합과 면적 벌점:

```
soft_flag = max(soft_general, soft_red)     # 검출기의 | 에 대응
soft_area = mean over valid pixels of soft_flag
L_risk    = softplus((soft_area − max_area_ratio) / τ_a) * τ_a
```

**두 항 모두 모델의 출력에 대해 계산한다** — 입력이 아니다. 검출기가 최종 결과물을 판정하듯, 손실도 결과물을 판정한다.

**valid 픽셀은 3.2절과 같다.** `L_risk`도 워핑된 프레임을 쓰므로 `BORDER_REPLICATE` 테두리를 같은 방식으로 제외한다. 제외하지 않으면 복제된 가장자리가 항상 델타 0으로 잡혀 면적이 실제보다 작게 나오고, 모델이 기준선을 넘었는데도 벌점을 덜 받는다.

`max`를 쓰는 것은 검출기가 두 마스크를 `|`로 합치기 때문이다. `softplus`는 `relu`와 달리 임계 아래에서도 (작지만) 0이 아닌 기울기를 남겨, 아슬아슬하게 통과한 상태에서도 여유를 확보하는 방향으로 미세하게 밀어준다.

**빈도 조건은 완화하지 않는다.** `detector.scoring.WindowedFlashCounter`는 `had_flag = area_ratio > 0.0`이므로 픽셀 하나만 넘어도 프레임이 flagged가 되고, 실측상 빈도는 항상 fps에 포화된다(cera 초반 9초, wonbon 전 구간에서 확인). `_is_risky`가 빈도 AND 면적이므로 **실질적으로 면적이 단독 판정 기준**이다. 빈도 항을 넣어도 상수 1을 곱하는 것과 같다.

### 3.4 기본 하이퍼파라미터

| 이름 | 값 | 근거 |
|---|---|---|
| `λ_t` | 1.0 | 2026-08-06 스모크 테스트에서 `temporal`(0.0251)이 `recon`(0.0766)의 1/3로, 무시되지도 압도하지도 않았다 |
| `λ_r` | 1.0 | 미검증. 1절의 진단상 이 항이 핵심이므로 약하게 시작할 이유가 없다 |
| `τ` | 0.02 | `delta_threshold`(0.1)의 1/5. 더 작으면 계단에 가까워져 기울기가 사라지고, 더 크면 실제 기준과 어긋난다 |
| `τ_a` | 0.05 | `max_area_ratio`(0.25)의 1/5. 같은 논리 |

모두 CLI 인자로 노출한다. `λ_r = 0`은 이 설계 이전의 목적함수(충실도 + 시간)로 되돌리며, 회귀 비교에 쓴다.

## 4. PriorCalc 변경

**목표 히스토그램을 제거한다.** 손실이 "얼마나 평평해야 하는가"를 직접 정의하므로 중복이고, 무엇보다 1절에서 진단한 **의미가 틀린 신호**다. `prior/histogram.py`와 `compute_illumination_histogram`은 사용처가 없어진다.

`compute_prior`가 반환하는 `FramePrior`는 다음이 된다:

```python
@dataclass
class FramePrior:
    frame_index: int
    mask: np.ndarray          # 0.2초 지속 OR, 현행 유지
    required_strength: float  # 이 프레임이 속한 위험 구간의 값
```

`required_strength`는 `fallback.strength.required_strength`를 구간 단위로 한 번 계산해 그 구간의 모든 프레임에 같은 값을 넣는다. 위험 구간에 속하지 않는 프레임은 `0.0`이다.

**마스크 지속(0.2초)은 유지한다.** 근거가 여전히 유효하다 — 원시 전이 마스크는 hold 프레임에서 손상 픽셀의 10.4%만 덮고, hold 프레임이 전체의 69%다. 다만 이 값은 옛 모델에서 측정된 최적치이므로, 재학습 후 재측정 대상으로 남긴다.

`prior_cache.npz`의 스키마가 바뀌므로 **기존 캐시는 전부 삭제해야 한다.**

## 5. 모델 변경

```python
in_channels = 3 * 3 + 1 + 1   # 3 RGB 프레임 + 마스크 + 강도
```

히스토그램 임베딩(`nn.Linear(64,32) → ReLU → Linear(32,16)`, 16채널)이 사라지고 **강도 스칼라 1채널**이 들어간다. 강도는 히스토그램과 같은 방식으로 `(B,1,1,1) → (B,1,H,W)` 브로드캐스트한다.

**강도를 넣는 이유**: 모델은 3프레임 윈도우만 본다. "이 구간이 얼마나 심한가"는 국소 정보로 얻을 수 없는 전역 맥락이다. 손실이 방향을 정해도 **작업량은 알려주지 않으며**, 실측상 모델은 자기 목표의 14.6%밖에 달성하지 못했다. Apple의 `m = (M/2)·log₁₀(max(1,q))`도 측정된 위험도에 비례해 강도를 정한다.

`in_channels`가 바뀌므로 **기존 `best.pt`(35.66 dB)는 로드할 수 없다.** 어차피 재학습하므로 문제되지 않지만, 비교용으로 보존한다.

## 6. 데이터

### 6.1 두 단계

**1단계 — 기존 합성 데이터.** `data/synthetic`의 188샘플에서 **`degraded` 프레임만** 사용한다. `clean` PNG(12.07 GB)는 손실 계산에 쓰이지 않는다. 목적은 데이터가 아니라 **손실 설계 검증**이다: `L_risk`가 실제로 `soft_area`를 내리는가.

`clean`을 즉시 삭제하지 않는다. 손실 설계가 실패하면 지도 학습으로 되돌아가야 하고, "자기지도가 지도 학습보다 나은가"를 같은 데이터에서 재려면 필요하다.

**2단계 — 실제 깜빡이는 영상.** 2026-08-07 기준 8개 확보, 검출기로 전부 위험 구간 확인됨. 5개는 학습(`data/raw/real_flicker/`), 3개는 평가로 분리(`data/raw/real_flicker_eval/`):

평균 Δ가 20배 폭으로 분포한다. 목표는 15~20개이며, 남은 수집에서 우선순위는 **개수가 아니라 두 빈칸**이다:

- **적색 스트로브** — 3.3절의 `soft_red` 경로를 검증할 데이터가 현재 없다.
- **카메라 움직임(핸드헬드)** — 3.2절의 전역 이동 보정이 이 설계의 최대 미검증 위험이다. 고정샷만으로는 검증되지 않는다.

또한 현재 8개가 모두 같은 스톡 사이트 형식(`NNNNN-NNNNNNNNN_medium`)이므로, 인코딩·촬영 스타일이 다른 유튜브 영상을 섞는다.

### 6.2 평가 세트는 절대 학습에 쓰지 않는다

**6개**: `test_mp4/`의 원본 / Anyma / Cera Khin, 그리고 `data/raw/real_flicker_eval/`의 3개. 같은 공연의 다른 구간도 제외한다. (2026-08-07 확인: `real_flicker/`, `real_flicker_eval/`, `test_mp4/`, `data/clips_final/` 사이에 중복 없음.)

앞의 3개만이 7절의 Tier 0 기준선(대비 −52.8% / −48.4%)과 **직접 비교 가능**하다. 그 숫자가 그 클립들에서 측정됐기 때문이다. 뒤의 3개는 절대 기준(위험 구간 0개)과 과잉 보정 여부만 본다. 뒤의 3개에서도 Tier 0 기준선이 필요해지면 `python -m fallback.cli`로 한 번 돌려 두면 된다.

## 7. 평가

정답 영상이 없으므로 **PSNR을 쓸 수 없다.** 대체 지표는 이미 정해져 있다 — Tier 0이 측정해 둔 기준선이다.

| 기준 | 값 | 출처 |
|---|---|---|
| 위험 구간 | **0개** (평가 6클립 전부) | Tier 0이 원본/Anyma/Cera에서 이미 달성 |
| 대비 손실 | **−52.8% / −48.4%보다 적을 것** | Tier 0 실측 (Anyma / Cera Khin) |
| 손상 범위 | 마스크 내부로 한정 | Tier 0은 구간 내 화면 전체 |

**세 번째가 신경망을 쓰는 유일한 이유다.** Tier 0은 시간축만 아끼고 공간축은 전역이다. 이를 못 넘으면 GPU도 학습 데이터도 필요 없는 고전 방식이 이긴다.

평균 밝기 변화는 **비용 지표로 쓰지 않는다.** 압축이 trailing 평균 쪽으로 수렴시키므로 구조적으로 거의 불변이며(wonbon은 오히려 +1.87% 상승), 이를 비용으로 보고하면 결과를 실제보다 좋게 보이게 한다.

에폭 선택은 검증 손실로 하고, 전체 검출기 평가는 학습 종료 후와 5에폭마다 수행한다(클립당 수십 초가 들어 매 에폭은 비현실적이다).

## 8. 구현 순서 — 0번은 게이트다

**Task 0 (게이트).** 실제 콘서트 클립에서 `estimate_global_shift`가 깜빡임 구간에 얼마나 버티는지 측정한다. 프레임별 밝기 정규화(각 프레임을 자기 평균으로 나눔) 전/후를 비교한다.

광학 흐름과 위상 상관은 **밝기 불변을 가정**하는데 스트로브가 정확히 그것을 위반한다. 2026-08-07에 랜덤 노이즈 클립에서 `cv2.phaseCorrelate`가 헛돌아 없는 위험 구간을 만들어낸 사례를 관측했다.

**이 검증이 실패하면 3.2절이 무너지고 나머지가 무의미하다.** 통과 기준: 깜빡임 구간의 추정 이동량이 인접한 비깜빡임 구간과 같은 크기 정도일 것. 실패 시 조밀 광학 흐름(OpenCV DIS)으로 승격하고, 그것도 실패하면 시간 항 자체를 재설계한다.

### Task 0 결과 (2026-08-07 실행): 통과

깨끗한 DAVIS 클립에 **인위적 깜빡임만** 주입해 측정했다. 기하학이 바뀌지 않으므로 정답 이동량은 원본과 동일하고, 어긋난 만큼이 곧 오차다.

| 조건 | 오차 (픽셀, dx+dy) |
|---|---|
| 전역 밝기 깜빡임 | **정확히 0** |
| 국소 깜빡임, 면적 10% | 0.011 – 0.179 |
| 국소 깜빡임, 면적 25% (ITU 기준선) | 0.013 – 0.252 |
| 국소 깜빡임, 면적 80% | 0.026 – 0.988 |

전역 깜빡임에서 오차가 0인 것은 위상 상관이 푸리에 **위상**으로 동작하고, 밝기 배율은 진폭만 바꾸기 때문이다. 국소 깜빡임은 구조를 바꾸므로 오차가 생기지만 기준선 면적에서 서브픽셀이다. **3.2절은 유효하다.**

### 게이트가 부수적으로 찾아낸 것: 폐기되는 신뢰도

같은 측정을 실제 클립 11개로 돌리자 480픽셀 프레임에서 **최대 1392.7픽셀**의 이동량이 나왔다. 원인은 깜빡임이 아니라 `detector/motion.py`가 `cv2.phaseCorrelate`의 두 번째 반환값(상관 피크 높이 = 신뢰도)을 버리는 것이다:

```python
(dx, dy), _ = cv2.phaseCorrelate(...)   # _ 가 신뢰도
```

신뢰도는 실패를 거의 완벽하게 예측한다 — 정상 추정 0.35–0.84, 쓰레기 추정 0.03–0.23. 근본 원인은 **주기적 구조**다. 같은 패턴이 반복되면 한 주기만큼 밀어도 똑같이 맞아 피크가 갈라진다. 57523 클립이 그 경우로, 깜빡임은 가장 약한데(평균 Δ 0.0047) 컷도 없이 299쌍 전부 실패한다.

**검출기에 미치는 영향은 작다.** 가드(임계 0.30) 적용 전후로 전체 판정을 비교하면 11개 중 9개가 구간 수·위험 프레임 수 모두 동일하다. 검출기가 구조적으로 관대하기 때문이다 — `had_flag = area_ratio > 0.0`이 빈도를 어차피 포화시키고, 면적은 1초 윈도우 최댓값이라 나쁜 프레임이 묻히며, 주기적 패턴에서는 틀린 이동량도 패턴을 다시 맞춘다.

**그러나 3.2절의 손실에는 중요하다.** 검출기는 임계화 → 면적 평균 → 윈도우 최댓값의 3단계로 오류를 뭉개지만, 시간 일관성 항은 `|워핑(out_i) − out_{i+1}|`의 픽셀별 L1 원값이라 걸러줄 단계가 없다. 300픽셀 틀린 워핑은 전 화면에 엉터리 기울기를 만든다.

`estimate_global_shift` 자체를 고치면 검출기와 손실이 계속 같은 값을 쓰므로 3.2절의 정합성 논리도 유지된다.
