# flicker-guard — 팀 공유용 요약

(기술 설계 문서는 [README.md](../README.md) 참고. 이 문서는 비개발 직군도 이해할 수 있게 쉽게 풀어쓴 버전입니다.)

## 우리가 풀려는 문제

**광과민성 발작(PSE)**: 특정 패턴으로 빠르게 번쩍이는 화면이 발작을 유발할 수 있습니다. 1997년 포켓몬스터 방영 사고(약 700명 병원 이송), 2018년 인크레더블2 스트로브 장면 실제 발작 신고 사례 등이 대표적입니다. 한국·일본·영국(Ofcom)·ITU 등은 이미 방송 콘텐츠에 대해 법적/강제 기준(플래시 주파수, 화면 면적, 밝기 변화량)을 두고 있습니다.

**목표**: 짧은 영상(광고·숏폼 등)이 들어오면, 이런 위험 구간을 자동으로 찾아서 눈치채지 못할 정도로만 살짝 고쳐주는 필터를 만드는 것입니다.

## 왜 기존 오픈소스(All-In-One-Deflicker)를 그대로 못 쓰는가

기존에 검토했던 모델(All-In-One-Deflicker, CVPR 2023)은 비유하자면 **"영상 한 편이 들어올 때마다 그 영상 전용 과외 선생님을 처음부터 새로 키우는"** 방식입니다. 실제로 34초짜리 영상 하나를 처리하는 데 40분이 걸렸습니다.

우리가 원하는 건 "영상을 재생하면 몇 초 안에 위험한 부분만 고쳐서 보여주는" 수준의 속도라, 이 방식으로는 구조적으로 불가능합니다. 그래서 처음부터 다시 설계했습니다.

## 어떻게 다르게 만들었나: 2단계 구조

**1단계 — 탐지**: 영상에서 "위험한 부분이 어디인지"를 아주 빠르게 찾습니다. 이건 AI 학습이 필요 없는 단순 계산(밝기 변화, 깜빡이는 주파수, 화면에서 차지하는 면적 측정)이라 거의 즉시 됩니다.

**2단계 — 완화**: 탐지된 위험 구간, 그것도 앞뒤로 조금의 여유만 포함해서 AI로 살짝 보정합니다. 영상 전체를 AI에 태우지 않고, 문제 되는 짧은 부분만 처리하기 때문에 훨씬 빠릅니다.

> 비유: 공항 보안검색대처럼, 모든 승객을 정밀검사하지 않고 먼저 스캔해서 걸린 사람만 추가로 검사하는 것과 같습니다.

## 왜 2단계에서 그냥 밝기만 낮추면 안 되나 (AI가 필요한 이유)

"위험한 부분을 찾았으면 그냥 코드로 밝기를 낮추면 되지 않나?"라는 질문이 자연스럽게 나올 수 있습니다. 답은 — **그것도 이미 있습니다.** 다만 AI가 실패했을 때 쓰는 "최후의 보험"(아래 안전장치 2번)으로 두고 있어요. 이유는:

- **눈에 띄면 안 됩니다.** 위험 구간을 그냥 강제로 어둡게 누르면 "이 부분만 갑자기 이상해졌다"는 게 바로 티가 납니다. 이 프로젝트의 목표 자체가 "눈치채지 못할 정도로만" 고치는 거라, 규칙으로 억지로 누르는 방식은 안전하긴 해도 목표에는 못 미칩니다.
- **장면마다 맞는 대응이 다릅니다.** "밝기 X% 낮춰라" 같은 고정 규칙은 그게 진짜 위험한 스트로브인지, 원래 연출 의도의 강렬한 번쩍임(폭발·번개 등)인지 구분하지 못합니다. AI는 주변 장면을 참고해서 좀 더 자연스럽게 맞춰 고칠 수 있습니다.
- **실제 위험 패턴은 깔끔한 도형이 아닙니다.** 화면과 함께 움직이는 불규칙한 광원처럼 복잡한 실제 상황에는 규칙 기반보다 AI가 더 정교하게 대응합니다.

그래서 구조는 "AI가 먼저 고품질로 고쳐보고, 실패하면 안전한 규칙 기반으로 물러난다"는 2단 방어입니다. AI가 힘들이지 않고 잘 고치도록, PriorCalc라는 부품이 미리 "이 장면은 원래 밝기가 이랬어야 한다"는 힌트를 계산해서 AI에게 넘겨줍니다 — AI가 맨땅에서 다 알아내는 게 아니라, 힌트를 참고해서 그쪽으로 자연스럽게 되돌리기만 하면 되도록 학습 부담을 줄여주는 역할입니다.

## 안전장치 — AI를 100% 믿지 않습니다

1. AI로 보정한 뒤, 다시 한번 1단계 탐지를 돌려서 "진짜로 안전해졌는지" 재확인합니다.
2. 안전해지지 않았다면 더 단순하고 확실한 고전적 보정 방식으로 대체합니다.
3. 그래도 안 되면 최후 수단으로 화면을 살짝 어둡게 하거나 잠깐 멈추는 식으로, **무조건 안전한 결과**를 보장합니다.

즉 AI 모델 하나에 모든 걸 맡기지 않고, 실패해도 항상 더 안전한 쪽으로 물러나는 구조입니다.

## 아이디어는 어디서 가져왔나

- **BlazeBVD** (논문, 코드 비공개): "화면 전체 픽셀 대신 밝기 변화 패턴만 뽑아서 가볍게 계산하면 AI 학습이 훨씬 쉬워진다"는 아이디어를 차용
- **Flickerformer** (논문+코드 공개): 실제로 돌려볼 수 있는 가벼운 AI 모델 코드. 원래 용도(짧은 연속 사진에서 조명 밴딩 제거)는 우리와 다르지만, 가볍고 빠른 구조라 아키텍처만 참고해서 우리 데이터로 새로 학습시킬 예정
- **All-In-One-Deflicker**: 이 프로젝트의 출발점이자, "왜 그대로는 못 쓰는지"를 보여준 비교 대상

## 중요한 전제 (꼭 기억할 것)

- 이 필터는 **의료기기가 아닙니다**. 실제 서비스에 넣기 전에는 Harding FPA 같은 검증된 외부 도구나 전문가 검토가 별도로 필요합니다.
- PSE는 법적 기준이 있는 영역이라 임의 기준이 아니라 한국/일본/영국/ITU 등 실제 규정을 그대로 따릅니다.
- "모든 발작을 막아준다"처럼 안전을 단정하는 표현은 쓰지 않습니다.
